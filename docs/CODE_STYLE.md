# JaiLib 编码约定

适用于第一方 core、kit、tools 和测试。Foster 与第三方移植保留来源的接口及组织，
不为统一外观改变 ABI、字段顺序或序列化格式。

## 功能组织与合并

先确定数据权威、生命周期、依赖和平台边界，再决定文件。共同维护一组不变式的声明和
过程放在同一主题；文件行数不是拆分或合并的标准。跨模块共享需要真实复用理由，
不增加只做转发的桥接模块。模块入口显式 `#load`，移动文件时核查作用域、相对资源路径和加载顺序。

复杂文件用中文 `//@region 主题`、`//@endregion` 导航；先 `rg -n "^//@(end)?region"` 查入口。
注释解释所有权、单位、格式、失败语义和非显然决策，不逐行翻译代码。

## Jai 约定

- 结构、枚举用 `Pascal_Case`，过程和变量用 `snake_case`，常量用大写；移植接口保持既有命名。
- 引擎和 UI 模块优先具名导入，例如 `F :: #import "foster";`，不要把所有导出摊到全局。
- `#scope_file` 用于文件私有实现，`#scope_module` 用于模块内部；明确需要的接口才导出。
- 泛型和 `#run` 用于消除重复或构建静态数据，不把可直接表达的运行逻辑转成代码生成框架。
- 动态数组、字符串、切片不是深拷贝；借用参数不由被调用者释放。跨帧保存时复制或引用稳定所有者。
- 显式传递 allocator 或使用明确生命周期的 `push_allocator`；不能把临时分配器的数据返回为持久资源。
- C ABI 使用明确宽度与调用约定；不得依赖 Jai `int` 与 C `int` 等宽。
- Jai `a..b` 包含两端，空容器循环优先 `for item: items`；不得机械照搬 Odin 半开区间。
- Jai 的 `if value == { case ... }` 不自动贯穿，多个空 case 不是组合匹配。
- 不从命名推断标准库行为；`table_find` 返回顺序、切片边界和运算符作用域以当前编译器为准。

## 验证

搬迁先核对声明、导入、资源和构建，再跑受影响测试。算法与格式改动用边界输入、失败原子性、
所有权和参考实现对拍验证；不以行数或符号数量代表等价。渲染/输入变化验收真实输出，
文档和目录改动不额外截图。完整命令见 [README](../README.md)。
