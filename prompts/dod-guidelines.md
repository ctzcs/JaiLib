# Jai 数据与依赖约定

适用于 JaiLib 与使用它的游戏。与 [新项目约定](new-project.md) 共同使用。

## 按数据形状选容器

- 批量同构处理使用数组；只有访问模式确有收益时才用 SoA。对象少、字段一起访问时保留结构数组。
- 需要稳定身份用 `core/handle`；删除/扩容后仍保存裸指针或数组行号是不安全的。
- 稀疏键查询用 Hash_Table；同时需要稳定遍历顺序时显式维护顺序，不依赖桶顺序。
- 不为所有数据自动引入 ECS；`core/entities` 只在实际需要组件组合时使用。

## 模块与依赖方向

Jai 不把同目录源码自动纳入模块，`module.jai` 与 `#load` 决定实际内容。
具名 `#import` 避免同名声明混入作用域；边界由真实导入图保证，不能通过转发模块绕过。

| 职责 | 可以依赖 | 不能依赖 |
| --- | --- | --- |
| 数据、类型、句柄、配置 | Basic/Math、纯 core | Foster、kit、编辑器、入口 |
| 规则、模拟、只读查询 | 数据和纯算法 | 渲染、输入设备、编辑器、入口 |
| 显示与音效 | 只读数据、Foster、kit、明确拆出的查询模块 | 修改规则状态、编辑器 |
| 游戏 core 组装 | 上述职责、资源与命令入口 | core_editor、editor、发布入口 |
| core_editor | core 公开接口、开发 UI | editor/game 入口 |
| game/editor 入口 | 相应组装模块和生命周期 | 另一入口 |

起步在 core 同模块分文件；实际需要独立边界才拆子模块。拆包后子模块不导入父包。
发布入口不可达 core_editor 或开发专用 ImGui，运行时关闭菜单不算隔离。

## 权威状态和内容

每个模拟实例独占自己的可变权威状态；全局仅放不可变表或明确的宿主服务。规则过程显式接收
状态、命令与 dt，渲染不暗改模拟数据。可同时创建两个世界，测试不得依赖进程级唯一实例。
内容用配置能力表达，避免在规则里按字符串 ID 特判；规则数组由内容安装入口统一重建。
代码默认值→全局配置→局部稀疏覆盖，加载候选完整校验后再替换，失败保留旧版本。
作者数据、模拟状态、派生缓存和 GPU 资源区分角色；同所有者且共同维护不变式的数据可保留同结构。

## 变化、快照和所有权

来源版本改变时统一刷新派生缓存，不用指针地址判断数据是否更新。事件表达变化事实，不能成为第二份状态。
Jai 的结构/切片/动态数组赋值是浅复制；快照含堆资源时独立复制并明确释放。
保存的是可恢复数据，不能包含 DLL 内部过程指针、GPU 对象、临时分配器字符串或输入捕获。
候选恢复成功后安装；失败不能改变当前实例。格式升级同时维护版本、缺省值与迁移测试。

## Jai 性能和确定性

热循环不做无必要的字符串拼接、临时分配和反射。编译期 `#run`、泛型用于生成可复核静态数据；
不假定 Odin 的字段标签、AST 或 `bit_set` 能直接用于 Jai。需要元数据时使用当前编译器支持的
类型信息，或普通显式描述表，并验证与结构一致。
固定步长模拟显式传 dt；随机数和时钟可注入。并行前明确写入集合、归并顺序和资源所有者。
Jai 范围 `a..b` 含末端；空数组、负索引、溢出、NaN、句柄复用都是需要覆盖的边界。

## 验证

规则测试不依赖窗口。验证多实例隔离、错误输入、复制/释放、保存恢复与缓存版本；
协议/数值移植用固定字节和参考轨迹对拍。纯类型检查带 `-no_dce`，也要运行行为测试。
游戏 tools/check 检查真实 `#import` / `#load` 依赖，不能沿用 Odin import 行解析器。
渲染与输入改动验收最终画面，生成目录遵循 [目录纪律](new-project.md#生成文件与目录纪律)。
