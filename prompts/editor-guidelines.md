# Jai 编辑工具开发约定

适用于对象变换、曲线、刷子、配置编辑等工具。编辑会话统一管理输入和生命周期，
工具负责交互，可保存内容通过编辑事务进入文档。本文件不表示 JaiLib 已提供通用编辑器框架。

## 目录与接入

项目专用编辑实现放 `src/core_editor`，开发入口放 `src/editor`；普通游戏状态和规则在 core。
无界面构建、转换和校验在根 tools，不再建 host 或 editor/play 转发层。
工具 UI 默认用 `thirdparty/imgui` 与 Foster 后端，玩家 UI 用 kit/ui。
先遵循 [新项目约定](new-project.md) 的编译器能力边界：jacket CLI 默认静态开发构建；
只有实际具备 Jai 共享库构建并验证过 ABI 后才接 DLL 热替换。下文恢复规则同样适用于普通场景切换。

文件按真实功能组织，不按固定行数拆分。编辑会话、文档、历史、视口和具体工具可同文件或分文件，
但所有权不能混淆。core 不导入 core_editor；发布入口不可达开发 UI。只读调试面板无需强加文档/撤销框架。

## 状态与所有权

| 状态 | 所有者 |
| --- | --- |
| 可保存对象、配置、路径 | 编辑文档，复用实际内容格式 |
| 当前文档、选择、工具、事务和历史 | 编辑会话，历史绑定对应文档 |
| 相机、视口、悬停 | 编辑视口，不写入内容 |
| 拖动起点、阶段和预览 | 工具跨帧状态，取消或停用时清理 |
| 试玩状态 | 独立模拟实例，默认不回写作者文档 |

用稳定 ID/有效句柄跨帧引用，不保存可能因扩容或删除失效的元素指针。开始操作时绑定目标，
后续选择变化不能悄悄转移目标。Jai 数组/字符串浅复制不构成独立试玩世界或撤销快照。
UI 上下文、GPU 对象和输入捕获不进入快照；恢复候选拥有独立内存，验证成功才安装。
DLL 恢复成功后重建 UI/GPU 资源，屏蔽已按住输入直到松开；服务 ABI 变化要求重启宿主。

## 生命周期与输入

工具经历激活→开始→更新→提交/取消→退出。输入由会话统一分配，工具不各自读取全局鼠标。
无捕获时先判断 UI、文本焦点和视口；已有捕获即使鼠标越过 UI 或移出视口仍接收移动、松开和取消。
文本编辑不能触发场景快捷键，一次输入只交给一个消费者。离焦、停用、切文档、删目标时先收尾再清理。
引用已失效时安全结束，不向复用 ID 的新对象写回。小型工具用枚举分发，不预建插件注册机制。

## 编辑事务与撤销

一次连续操作对应一条事务，可跨帧、可改多个对象。开始记录完整恢复数据；更新校验后应用，
拒绝时保留上一份有效预览；提交有实际变化才入历史；取消恢复起点且不新增历史。
最终回到原值不生成空记录。新事务提交才清除重做分支，取消不清除。
多对象修改保持原子性；不能通过重新执行普通玩法命令假装恢复，因为规则和外部状态可能已变。
一次帧内可同时开始、更新和结束，必须保留起始数据并应用最后有效更新，取消优先于提交。
默认一个文档只允许一个活动修改事务，撤销、保存、试玩或切工具之前显式提交或取消。

## 变化、保存与试玩

正常编辑、取消、撤销/重做共用变化入口，同步派生数据、空间索引和 GPU 缓存。
未保存状态依据内容与最后成功保存的内容是否相等，不用单调版本号或历史数量代替。
加载完整候选后替换；保存失败保留旧文件及未保存状态，采用同目录临时文件原子替换。
试玩从文档深拷贝独立实例，调试命令进入规则函数；“应用试玩结果”若提供，必须是显式编辑事务。
源配置和模拟参数不维护两套互相竞争的权威值。

## 视口与验证

统一窗口坐标→视口局部坐标→场景坐标转换，输入和绘制使用同一套变换。
UI 按最终物理像素绘制，场景放大不连带放大 UI。检查 resize、偏移视口、非整数缩放和最终文字清晰度。
事务测试覆盖取消、无变化、多对象失败原子性、删除/句柄复用、切文档、撤销回保存点、保存失败。
真实交互验证 UI 不穿透、拖出仍松开、文本不触发快捷键、离焦能结束。
目录和文档变更不截图；必要截图放 `library/screenshots`。检查入口用项目 tools/check，
不以编译成功替代交互和像素验收。
