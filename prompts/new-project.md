# JaiLib 新项目约定

将以下约定用于创建 Jai 游戏。先读取本仓库 README、[数据约定](dod-guidelines.md)、
[编辑工具约定](editor-guidelines.md) 与 [编码约定](../docs/CODE_STYLE.md)。
项目需求、平台、规模和用户明确的约束优先于默认模板；不要复制 Odin 命令和 API 名称。

## 提示词开始

请基于 JaiLib 创建可构建、可运行、可测试的 Jai 游戏。先实现最小可玩的闭环，逐步加入玩法。
以数据、规则、显示和所有权边界组织代码，不预建 ECS、编辑器框架或插件系统。

### 技术栈和依赖

- 使用 Jai 与 jacket `jaic`，通过 `-import_dir <JaiLib>` 导入 `foster`、`core/...`、`kit/...`。
  不需要同级 jfoster，也不把 JaiLib 的模块复制到游戏中。
- Foster 是唯一窗口、输入和 GPU 运行时。游戏 UI 用 `kit/ui`，开发 UI 用 `thirdparty/imgui`
  及 `thirdparty/imgui/imgui_foster`。二进制必须与仓库绑定配套。
- 运行时资源使用 Foster/kit 的已有入口；项目业务资源放自身 assets，默认字体/图标可来自 JaiLib/assets。
- `jaic` 0.35.1 的 CLI 没有 DLL 输出选项。不要生成 `odin build`，也不要承诺自动 DLL 热重载。
  默认交付静态开发入口；需要 DLL 时使用实际支持共享库的 Jai 构建流程，先做 ABI 与加载烟测，
  再接 `core/hotreload` 的显式构建命令。库能监听/加载 DLL 不等于编译器能生成它。

### 目录结构

```text
src/core/          游戏实例、规则、显示、快照；services.jai 管共享资源协议
src/core_editor/   开发会话、面板、编辑命令；按实际需求扩展
src/editor/        开发入口，只组装生命周期和会话
src/game/          发布入口，只接游戏 core
tests/             与被测模块对应的无窗口回归
tools/             构建、转换、检查和发布入口
assets/            业务正式资源及许可
build/             可重新生成的构建、测试、发布产物
```

模块使用 `module.jai` 明确加载文件。core 起步在同模块按主题分文件；真实依赖或复用边界出现时
才拆 `core/data`、`core/logic`、`core/view` 等子模块。子模块不能反向导入 core 父模块。
不创建第二份权威状态，也不增加 host、editor/play 等转发层。

### 生成文件与目录纪律

- 截图放 `library/screenshots`，图像候选/提示词放 `library/imagegen`，诊断脚本/报告放 `library/tmp`。
  按需创建，同场景复用文件名；不按日期或任务在根目录新建输出目录。
- build 只放构建、测试、发布产物及日志。正式字体、图标、预编译 shader 不按临时文件清理。
- 临时工作区独占创建、按所属生命周期释放。同目录原子保存必须留在目标文件所在卷，
  不为集中输出破坏原子替换。library 不整体删除或随发布包分发。
- 文档、目录、配置变更不额外截图；渲染与交互变更按需要验收最终输出。

### 状态、规则和内存

游戏状态由实例拥有，过程显式接收状态、输入和 dt。规则可无窗口调用；UI 只读状态并产生命令。
数组扩容可能使元素指针失效，跨帧引用优先稳定句柄。结构赋值不能代替动态数组/字符串的深拷贝。
每个资源写明创建、借用、转移、释放位置；退出、失败和候选被拒路径同样释放。
配置安装先完整校验，再替换并重建派生缓存；失败保留旧配置。快照版本、默认值和迁移随状态同步。

### 桌面与 Web 发布入口

发布只编译 `src/game` 可达图，不能靠隐藏开发面板来排除编辑器。Web 使用 Foster 的 wasm64
宿主桥；先确认目标浏览器支持 Memory64/table64，再验证输入、存储和像素。不可直接使用 Odin
JS runtime、Emscripten 配方或桌面 ImGui DLL。不要把纯编译成功称为已支持 Web。
着色器源码与 Compiled 产物同步；私有工具依赖不进入游戏发布包。

### UI 用什么以及如何接入

玩家 UI 使用 kit/ui；编辑器使用仓库内 ImGui 与 Foster 后端。App.update 接入输入，render
开始一帧 UI，最后提交绘制；上下文和 GPU 纹理由同一会话创建与释放。
UI 按最终物理像素排版，低分辨率场景单独放大。中文从已提供的字体及其许可起步，
缺字、字体大小、3D 抗锯齿分别验收，不用加粗代替采样排查。
输入由会话统一分配，文本输入和 UI 捕获期间不能同时触发游戏快捷键。

### 创建与验证流程

1. 确认项目名、目标路径和最小玩法，用 `tools/new-game` 生成器创建不存在的目标目录。
2. 编译游戏与开发入口，运行无窗口状态测试；再运行窗口核对输入、尺寸和绘制。
3. 实现玩法时维护状态所有权、快照和错误语义，不增加无用途的抽象层。
4. 发布到独立 build 子目录，检查动态库、资源及发布依赖。热重载、Web 只报告实际验证过的能力。

最终给出入口、命令、通过的检查和明确限制，不以 TODO 或模拟数据代替承诺的功能。
